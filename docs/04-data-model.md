# 04. Data model

Conventions for every service:
- Primary keys are UUID v7 (time-ordered), generated by the application, never by the database.
- Every table with household data has `household_id UUID NOT NULL` and an index starting with it.
- `created_at TIMESTAMPTZ NOT NULL DEFAULT now()`, `updated_at TIMESTAMPTZ NOT NULL`, maintained by the application.
- Money columns come in pairs: `<name>_minor BIGINT NOT NULL` and `currency CHAR(3) NOT NULL DEFAULT 'DKK'`. No NUMERIC, no FLOAT.
- Soft delete only where the domain says so (`archived_at` on categories, `status = VOID` on expenses). Otherwise real deletes, driven by GDPR flows.
- Enums are `TEXT` columns with a `CHECK` constraint listing the values, so migrations stay simple.
- Every service has `processed_events (event_id UUID PRIMARY KEY, processed_at TIMESTAMPTZ)` and, if it produces events, `outbox (id UUID PK, aggregate_type TEXT, aggregate_id UUID, event_type TEXT, payload JSONB, headers JSONB, created_at TIMESTAMPTZ, published_at TIMESTAMPTZ NULL)` with an index on `published_at NULLS FIRST`.

## core-service

```sql
households (
  id UUID PK,
  name TEXT NOT NULL,
  currency CHAR(3) NOT NULL DEFAULT 'DKK',
  time_zone TEXT NOT NULL DEFAULT 'Europe/Copenhagen',
  settings JSONB NOT NULL DEFAULT '{}',     /* llm_notes_opt_in bool, receipt_retention_days int */
  created_at, updated_at,
  deletion_requested_at TIMESTAMPTZ NULL
)

members (
  id UUID PK,
  household_id UUID NOT NULL REFERENCES households,
  user_id UUID NOT NULL,                    /* Keycloak subject */
  display_name TEXT NOT NULL,
  avatar_media_id UUID NULL,
  role TEXT NOT NULL CHECK (role IN ('OWNER','ADULT','LIMITED')),
  joined_at TIMESTAMPTZ NOT NULL,
  left_at TIMESTAMPTZ NULL,
  UNIQUE (household_id, user_id)
)
INDEX members (user_id)

invitations (
  id UUID PK,
  household_id UUID NOT NULL,
  created_by_member_id UUID NOT NULL,
  role TEXT NOT NULL,
  token_hash TEXT NOT NULL UNIQUE,          /* only the hash is stored */
  expires_at TIMESTAMPTZ NOT NULL,
  accepted_by_user_id UUID NULL,
  accepted_at TIMESTAMPTZ NULL
)

categories (
  id UUID PK,
  household_id UUID NULL,                   /* NULL means system default template */
  parent_id UUID NULL REFERENCES categories,
  name TEXT NOT NULL,
  kind TEXT NOT NULL CHECK (kind IN ('FIXED','VARIABLE','DISCRETIONARY')),
  icon TEXT NULL,
  sort_order INT NOT NULL DEFAULT 0,
  archived_at TIMESTAMPTZ NULL,
  created_at, updated_at
)
INDEX categories (household_id, parent_id)
/* Depth is enforced in the domain (max 3), and by a trigger as a safety net. */

expenses (
  id UUID PK,
  household_id UUID NOT NULL,
  created_by_member_id UUID NOT NULL,
  category_id UUID NOT NULL REFERENCES categories,
  amount_minor BIGINT NOT NULL CHECK (amount_minor > 0),
  currency CHAR(3) NOT NULL DEFAULT 'DKK',
  occurred_on DATE NOT NULL,
  merchant TEXT NULL,
  note TEXT NULL,
  source TEXT NOT NULL CHECK (source IN ('MANUAL','RECEIPT','INVOICE','BANK','RECURRING')),
  status TEXT NOT NULL CHECK (status IN ('DRAFT','CONFIRMED','VOID')),
  document_id UUID NULL UNIQUE,             /* one document, one expense */
  recurring_rule_id UUID NULL,
  recurring_occurrence_on DATE NULL,
  confirmed_at TIMESTAMPTZ NULL,
  voided_at TIMESTAMPTZ NULL,
  version INT NOT NULL DEFAULT 0,           /* optimistic locking */
  created_at, updated_at,
  UNIQUE (recurring_rule_id, recurring_occurrence_on)
)
INDEX expenses (household_id, occurred_on DESC)
INDEX expenses (household_id, status, occurred_on)
INDEX expenses (household_id, category_id, occurred_on)

expense_items (
  id UUID PK,
  expense_id UUID NOT NULL REFERENCES expenses ON DELETE CASCADE,
  household_id UUID NOT NULL,
  line_no INT NOT NULL,
  description TEXT NOT NULL,
  quantity NUMERIC(10,3) NULL,              /* quantities are not money; NUMERIC is allowed here */
  unit TEXT NULL,
  unit_price_minor BIGINT NULL,
  line_total_minor BIGINT NOT NULL,
  is_deposit BOOLEAN NOT NULL DEFAULT false,
  product_hint TEXT NULL,
  UNIQUE (expense_id, line_no)
)

tags (id UUID PK, household_id UUID NOT NULL, name TEXT NOT NULL, UNIQUE (household_id, name))
expense_tags (expense_id UUID, tag_id UUID, PRIMARY KEY (expense_id, tag_id))

recurring_rules (
  id UUID PK,
  household_id UUID NOT NULL,
  created_by_member_id UUID NOT NULL,
  category_id UUID NOT NULL,
  amount_minor BIGINT NOT NULL,
  currency CHAR(3) NOT NULL DEFAULT 'DKK',
  merchant TEXT NULL,
  note TEXT NULL,
  schedule JSONB NOT NULL,                  /* {"freq":"MONTHLY","interval":1,"byMonthDay":1} etc. */
  starts_on DATE NOT NULL,
  ends_on DATE NULL,
  auto_confirm BOOLEAN NOT NULL DEFAULT false,
  generate_days_ahead INT NOT NULL DEFAULT 7,
  archived_at TIMESTAMPTZ NULL,
  created_at, updated_at
)

documents (
  id UUID PK,
  household_id UUID NOT NULL,
  uploaded_by_member_id UUID NOT NULL,
  media_id UUID NOT NULL UNIQUE,
  kind TEXT NOT NULL CHECK (kind IN ('RECEIPT','INVOICE')),
  state TEXT NOT NULL CHECK (state IN ('QUEUED','EXTRACTING','EXTRACTED','FAILED','REJECTED')),
  expense_id UUID NULL,
  failure_reason TEXT NULL,
  created_at, updated_at
)
```

## media-service

```sql
media_objects (
  id UUID PK,
  household_id UUID NOT NULL,
  uploader_user_id UUID NOT NULL,
  s3_key TEXT NOT NULL UNIQUE,              /* households/{household_id}/{id}.{ext} */
  mime TEXT NOT NULL,
  size_bytes BIGINT NULL,
  sha256 TEXT NULL,
  status TEXT NOT NULL CHECK (status IN ('PENDING','UPLOADED','DELETED')),
  thumbnail_key TEXT NULL,
  retention_until TIMESTAMPTZ NULL,         /* NULL = keep while linked expense exists */
  created_at, updated_at
)
INDEX media_objects (household_id, created_at)
INDEX media_objects (retention_until) WHERE status = 'UPLOADED'
```

## insights-service, market-ingest, notifications-service

Detailed in their milestone files (`tasks/M4.md`, `tasks/M5.md`, `tasks/M7.md`). They follow the same conventions. insights-service adds `embeddings (id, household_id, source_type, source_id, embedding VECTOR(1024), text_redacted TEXT)` using pgvector with an HNSW index filtered by `household_id`.

## GDPR data map

| Data | Where | Retention | Deleted by |
|---|---|---|---|
| Identity (email, external ids) | Keycloak | account lifetime | Keycloak admin API on account deletion |
| Membership, expenses, rules | core-service | household lifetime | `HouseholdDeletionRequested` flow |
| Receipt images | S3 via media-service | `receipt_retention_days` (default 90) after confirmation, or until expense voided | retention job, deletion flow |
| Extraction raw responses | documents-worker | 30 days | retention job |
| Projections | forecasting, insights, market | rebuilt; deleted on household deletion | deletion flow consumers |
| LLM provider side | provider | per provider policy; zero-retention endpoints preferred | contractual |
